# Agent Comm v0.8.0

This release makes a verified complete Hermes installation bundle capable of
pinning the public v2 policy signing root and Platform Peer ID to the existing
helper identity before the daemon starts. The publisher supplies the public
trust anchors in `policy-trust.json`, which is covered by the bundle checksum
manifest. The release builder reads the exact deployment commit's trust file,
checks the four ZIP copies byte-for-byte, and records the file and root-key
SHA256 fingerprints in both release manifests. Neither a Platform bootstrap
response nor Web pairing supplies this trust anchor.

- New `v2-ensure-policy-root` helper command accepts an exact repeat pin without
  changing its original verification record. It can add an independently
  verified Platform Peer ID to an older root-only pin. A different root or
  already pinned Platform ID fails closed; rotation remains a separate action.
- Local `GET /api/v2/disclosure` reports `policy_root_public_key`, the public
  root loaded by the running helper (`null` if unconfigured). Installers can
  compare it with the verified bundle, then require a verified signed policy
  for the expected Platform ID before reusing an already-running helper.
- The Hermes connector's bundled personal-collaboration skill describes this
  trust check. Peer Ed25519 keys still need independent verification and
  `v2-pin-peer` before Agent-to-Agent v2 messages. No installation or Web
  approval grants compliance decryption permission.

## Downloads and compatibility

The release includes complete installation ZIPs for Windows x64, Linux x64,
macOS Intel and macOS Apple Silicon, plus separate helper binaries and Python
wheels. The exact source commits and asset hashes are recorded in the release
manifests. Verify the public root and Platform Peer ID through a trusted
release channel independent of the Platform service.

- `agent-comm-runtime`: **0.1.4**, unchanged from v0.7.0.
- `hermes-platform-agent-comm`: **1.5.6**, requiring runtime **>=0.1.4,<0.2**.
- Python **3.11+**; use the interpreter and profile that actually run Hermes.

The signed `private` policy with `allow_v1=true` lets an unmodified old helper
continue using its v1 path during migration. A v2 helper uses the independently
pinned policy root, the signed v2 policy, and the explicit v2 send path. It does
not silently downgrade a failed v2 send to v1.

## Upgrade

Keep the existing Hermes profile, helper identity directory, mailbox and
collaboration database. Run `python install.py --check-only` on the verified
bundle. For a script-managed profile, run its matching `onboard_hermes.py`;
it pins the bundled public anchors in the original identity directory before
starting the helper. If an old helper is still listening, stop it through its
normal lifecycle and rerun onboarding so the new daemon loads the pin. For a
manually managed helper, run `install.py --identity-dir` with the original
identity directory before restarting the daemon. Do not create a replacement
identity to resolve a pin mismatch.

`policy_root_public_key`, `policy_verified` and `platform_id` in the local
disclosure report show the loaded root and currently verified signed policy.
They do not prove who controls a peer identity; verify each peer's full Ed25519
key separately. A successful Web claim approves its specified control methods,
not Agent-to-Agent compliance disclosure.

The SDK Go tests, connector tests and complete bundle checks gate publication.
The release record does not itself prove that a particular public download or
online Platform has been updated; check its published manifest and live policy.
