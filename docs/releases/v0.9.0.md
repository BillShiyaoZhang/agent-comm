# Agent Comm v0.9.0

This release lets two agents registered on the same Platform start a contact
request with the recipient's exact URN. The helper resolves the recipient's
owner-signed Registry record, verifies its Ed25519 key against the URN, checks
the derived PeerID and signed X25519 key, and uses that binding for the signed
v2 handshake. A receiving helper can verify an unknown sender through Registry
before presenting the request to the owner. Existing manual peer pins remain
authoritative: an automatically discovered key cannot replace a conflicting
pin. Manual `v2-pin-peer` remains available for independent checks.

Cryptographic verification establishes control of an agent URN. It does not
establish the real-world identity of the person or organization behind it.
Owners who intend to connect specific people should exchange exact URNs through
a channel they trust. The recipient may accept or reject the request. Acceptance
establishes a `connected` communication relationship; it does not set
`trusted`, grant collaboration or Web permissions, authorize tool or resource
access, or consent to Platform compliance decryption. Those decisions retain
their separate controls.

The Python runtime requires a connected contact before it sends ordinary
private messages or v1/v2 business dispatches. It quarantines and ACKs business
messages from unknown or rejected senders; contact requests and responses can
still arrive so the owners can decide. Messages from an already known pending
contact that arrive before its acceptance response can become visible after the
response is processed. The low-level Go helper checks protocol identity and
policy, but does not consult the runtime's contact state; applications using it
directly must enforce their own contact permissions.

## Downloads and compatibility

The release includes Windows x64, Linux x64, macOS Intel and macOS Apple
Silicon helper binaries, two Python wheels, four complete Hermes installation
ZIPs, and source and documentation archives. Verify the published asset and
bundle manifests before installation. The complete ZIP carries the reviewed
public policy-signing root, expected Platform PeerID, HTTPS origin and their
checksums in `policy-trust.json`; the Platform bootstrap response is not a
substitute for those release trust anchors.

- `agent-comm-runtime`: **0.1.5**.
- `hermes-platform-agent-comm`: **1.5.7**, requiring runtime **>=0.1.5,<0.2**.
- Python **3.11+**; use the interpreter and profile that actually run Hermes.
- Both agents need the v0.9.0 helper for URN-only first contact. The older
  v0.8.0 helper still requires independent full-key verification and a manual
  `v2-pin-peer` on both sides.

This first-contact flow is for agents on one Platform. Cross-Platform discovery,
trust exchange and routing are not included.

## Upgrade

Keep the existing Hermes profile, helper identity directory, mailbox,
collaboration database and Web pairing. Verify the complete ZIP and run
`python install.py --check-only` with the Hermes interpreter. Stop the old
helper through its normal lifecycle, install the included wheels, pin the
bundle's reviewed public policy anchors to the **original** identity directory
if needed, and start the new helper with that directory. For a script-managed
profile, use the matching `onboard_hermes.py` and confirm it restarted the
correct helper. Do not initialize a replacement identity to work around a
conflicting existing pin.

Check the local `GET /api/v2/disclosure` report for the exact verified signed
policy and loaded public root. If the Platform runs `compliance`, each owner
must separately review and authorize the exact policy on that agent's device;
installing v0.9.0, accepting a friend request, and confirming Web access do
not grant this consent. Confirm success with the actual request, acceptance,
message delivery, decrypt and ACK states. An HTTP 202 or locally queued
request alone does not prove the other agent received anything.

Published assets, a production deployment and a real Hermes two-agent test
must each be verified independently of the source commit.
