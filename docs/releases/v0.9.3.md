# Agent Comm v0.9.3

This client release connects paired Web conversations to the tasks, exact approvals and bilateral collaborations that the local agent actually prepares. Trusted Hermes running-turn context creates `source_context.origin=paired_conversation`; model text and tool arguments cannot manufacture it. A direct authenticated `collaboration.execute` RPC keeps its separate `paired_control` principal and does not require a running model turn. When the adapter advertises `describe.source_context_support.version=1`, the Web client may provide `source_conversation_id`; the bridge verifies that the pairing owns a stored conversation and records navigation provenance without granting new rights.

Existing `conversation.get` responses add optional `turns[].related` references and `history={limit:100,returned,truncated}`. Old records return empty references instead of guessing from model output. Creation provenance remains stable when later turns update the same object. The stored history boundary is still the latest 100 turns returned by the agent, not full conversation discovery or pagination.

Existing authorized `attention.list` reads now include durable conversation lifecycle items. Submitted and running versions are resolved progress; terminal versions are a single result notice with `{kind:conversation,id:conversation_id,turn_id}`. Safe summaries contain no private prompts, replies or error text. Completion means the model turn ended; business completion still requires actual collaboration evidence. Failure and interruption do not grant permission to repeat an operation. The Web client can return to the exact turn, while the Hermes native companion displays context without submitting a new native handling request for this remote result notice.

Turns remain serial, including claims from multiple workers. Restarting marks a previously running turn interrupted rather than replaying uncertain tool side effects. A crash after terminal commit but before notice projection is repaired idempotently from the saved turn; repeated reads do not create new notification revisions. Existing owner isolation, exact current approval checks, local pairing method scopes and expiry continue to apply. This release does not add arbitrary execution, calendar writes, streaming, attachments, turn cancellation, automatic model wakeups or authorization renewal.

## Packages and upgrade

- `agent-comm-runtime` **0.1.8**.
- `hermes-platform-agent-comm` **1.5.10**, requiring runtime **>=0.1.8,<0.2**.
- Python **3.11+** in the interpreter that actually runs Hermes.

Keep the original identity, profile, helper mailbox, collaboration and remote databases, and pairings. Verify the official platform ZIP, manifest and included `policy-trust.json`; run `install.py --check-only` with the Hermes interpreter, upgrade the matching wheels, and restart the connector through the existing installation workflow. Existing pairings are not expanded. These additive records need no identity reset. The v0.9.2 full-terms acceptance-card migration remains in place and must not be bypassed by rolling back to older authorization code.

Publication, website synchronization, local installation upgrade and a real model/agent outcome are separate checks. This note describes the release behavior; refer to the deployment release record for the actual published assets and verification results.
