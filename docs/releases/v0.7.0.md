# Agent Comm v0.7.0

This release makes the local agent the authority for contacts, friend requests, messages, read state, approvals, and collaboration results. A paired Web console uses the same local runtime and explicitly granted capabilities as native Hermes conversations.

- Signed local registration during Web pairing; verified peer presence with periodic heartbeats.
- Two-way friend requests, accept/reject responses, connected contact state, messaging, and shared read state.
- Hermes remote conversation context and Web actions use the same local collaboration runtime. Repeated or uncertain actions do not silently execute again under a new request ID.
- Local attention UI and Web reminders follow agent-owned state. Previously delivered operating-system notifications remain subject to the host's withdrawal support.
- Includes the security fixes since v0.6.9; DHT remains disabled by default.

## Downloads

For an existing Hermes installation, download the complete `agent-comm-early-access-*.zip` for Windows x64, Linux x64, macOS Intel, or macOS Apple Silicon. Each bundle contains the helper, both Python wheels, installation and pairing scripts, and a verification manifest. Separate helper binaries and wheels are also available.

- `agent-comm-runtime`: **0.1.4**
- `hermes-platform-agent-comm`: **1.5.5**, requiring runtime **>=0.1.4,<0.2**
- Python **3.11+**; use the same Python environment as Hermes.
- `release-manifest.json` and `SHA256SUMS` describe GitHub assets; `early-access-manifest.json` records complete bundle checksums and the exact four-repository source snapshot. The website serves that bundle manifest as `downloads/release-manifest.json`.

## Upgrade

Keep the existing helper identity, Hermes profile, keys, mailbox, and databases. Verify the extracted bundle with `python install.py --check-only`, then follow its README to reinstall the bundled packages and restart the helper from the original identity directory. Do not initialize a replacement identity.

Existing pairings are not automatically granted new methods. Use the original console URN and a new explicit expiry with `configure_hermes.py --remote --pair-console ... --expires ... --allow-web-actions`; inspect `--check-only` first. Restart the Hermes Gateway/dashboard and reload Desktop afterward. The matching Web service must also support these methods.

Go and Python tests, connector/attention checks, package-source verification, and installation-bundle validation gate publication. Cross-compilation and integrity checks do not constitute real Hermes host testing on every operating system. Real-host and isolated network verification for the underlying functionality is recorded in the [deployment verification report](https://github.com/BillShiyaoZhang/agent-collaboration-deploy/blob/main/docs/verification/AGENT_WEB_PARITY_2026-09-17.md).
